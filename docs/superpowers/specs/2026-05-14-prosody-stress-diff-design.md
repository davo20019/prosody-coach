# Prosody Stress Diff — Phase 1 Design

**Date:** 2026-05-14
**Status:** Spec — pending user approval
**Scope:** Drill mode only (`/drills/run/...`). Practice and Frameworks unchanged.

## Goal

Sharpen the self-monitoring loop in drill mode by showing learners *what they actually stressed* against *what was expected*, in a layout that leads with a plain-English verdict, keeps a visible syllable-level diff, and trims the current 5-chip metric row down to the dimensions the diff doesn't already cover.

Three product changes ship together as one phase:

1. **Verdict-first** result layout (one sentence naming the most actionable miss).
2. **Per-syllable stress diff strip** as the always-visible visualization.
3. **Reduced metrics surface** above the fold (2 chips: Pitch range, Pauses) with the rest pushed into a "Coach notes & details" drawer.

Items #3 (shadowing mode) and #4 (longitudinal tracking) from the original five-item list are explicitly out of scope for this phase. They get their own specs after this one ships and is validated.

## Non-goals

- No reference audio playback. The project previously decided against TTS-as-model (`main.py:1238` — *"IPA shows pronunciation - no TTS to avoid bad rhythm model"*) and this phase preserves that decision.
- No new settings UI. The diff is on when its prerequisites are available; otherwise the page falls back to the current 5-chip layout.
- No changes to the existing `ProsodyAnalysis` pipeline. The 5 metric scores keep being computed; only their *presentation* changes.
- No changes to Practice page, Frameworks runner, or History detail. Phase 2 considers extending to Practice.

## Architecture

### Pipeline (drill result rendering)

```
prompt text ─► CMU dict lookup ──► target stress pattern per syllable
                       │
                       └─OOV───► existing coach.stress_pattern (LLM fallback)
                                          │
recording ─► whisper word timings ─► syllable-boundary estimator ──┐
                                                                    │
                                          per-syllable f0 / amp ────┤
                                          (DSP, no LLM)             │
                                                                    ▼
                                                     PerSyllableProsody[]
                                                                    │
                                                                    ▼
                                                     StressDiff (target ↔ actual)
                                                                    │
                                                                    ▼
                                                     verdict (rule-based, one sentence)
                                                                    │
                                                                    ▼
                                          drill_run.html → analysis_card.html
                                          (verdict + syllable strip + 2 chips + drawer)
```

### Architectural choices and why

**Whisper-first, BFA-optional.** Stress diff runs with only whisper word timings + vendored CMU dict + DSP — no BFA required. This is the long-term-correct posture for an OSS project: the killer feature must work without a heavy ML stack install. BFA, when available, provides tighter phoneme boundaries and is used automatically as an accuracy upgrade. Aligner-availability is a quality dial, not an on/off switch.

**Vendored CMU Pronouncing Dictionary.** Ship `data/cmudict-0.7b.txt` (~3.6 MB, public domain) directly in the repo with a small stdlib parser. No new PyPI runtime dependency. Frozen data, zero install friction, zero supply-chain surface.

**Rule-based verdict, not LLM.** The verdict line is generated by a small template function over the diff entries — fast, deterministic, and works the same on cloud and local coach setups. The LLM (cloud or local llama.cpp) still produces the *coach drawer notes*, where soft variance is acceptable.

**Existing `ProsodyAnalysis` untouched.** All 5 scores keep being computed. Pitch and Pauses surface as chips above the drawer; Volume, Tempo, and Rhythm move into the drawer (Rhythm's story is now told by the syllable strip).

## Components

### New: `syllable_prosody.py`

Given whisper word timestamps and audio path, returns per-syllable prosody descriptors.

```python
@dataclass
class PerSyllableProsody:
    syllable: str          # e.g. "in", "tro", "duce"
    word_index: int        # which word in the prompt this syllable belongs to
    syl_index_in_word: int
    start: float           # seconds
    end: float
    f0_peak: float | None  # Hz, None if voiceless / no f0 detected
    mean_amp: float        # normalized 0-1 across the utterance
    duration: float        # end - start, seconds
    stress_score: float    # 0-1, see "Stress score derivation"

def score_syllables(
    audio_path: Path,
    word_timings: list[WordTimestamp],
    syllable_counts: dict[str, int],    # from CMU dict: word -> syllable count
    aligner_result: AlignmentResult | None = None,  # optional, for BFA upgrade
) -> list[PerSyllableProsody]: ...
```

**Syllable-boundary estimation (when BFA unavailable):**
- For each word, look up syllable count from CMU dict (count of vowel phonemes in the entry).
- Split the word's whisper-timed interval into N sub-intervals weighted by a **sonority weight table**: vowels = 3.0, sonorant consonants (L, R, M, N, NG, W, Y) = 1.5, voiced obstruents = 1.0, voiceless obstruents = 0.7. The table is small and tunable in a constants block in `syllable_prosody.py`. This is a heuristic — it doesn't try to syllabify, just to place boundaries near the right *positions* relative to the syllable nuclei.
- Where CMU has multiple pronunciation entries (e.g. `RECORD` vs `RECORD(2)` — the noun and verb forms have different stress), v1 uses the first entry. POS-aware selection is a known limitation; see Risk register.

**Pitch & amplitude extraction:** reuse `parselmouth` (Praat bindings), already used by `analyzer.py` for `analyze_pitch` and `analyze_volume`. Build the `parselmouth.Sound` once per recording, then query f0 (`Pitch.to_array` or `call(sound, "Get value at time...")`) and intensity per syllable interval. No new audio-processing dependency.

**When BFA is available:** use BFA's phoneme boundaries directly to find vowel nuclei and place syllable boundaries at the consonant-vowel transition before each nucleus. Strictly better, no fallback needed.

**Stress score derivation:**
- For each syllable, compute three z-scores within the utterance: f0 peak (over voiced frames), mean amplitude, and duration.
- `stress_score = clamp01(0.5 * z_f0 + 0.3 * z_duration + 0.2 * z_amp + offset)`
- Weights and offset chosen so that primary-stressed syllables in a typical English utterance score above 0.6 and unstressed ones below 0.4. The threshold for "actually stressed" is 0.55 with hysteresis: a 0.4–0.55 syllable on a content word that's expected to be stressed is treated as "weak" rather than "missed."
- These weights are tunable; the spec doesn't lock them in.

### New: `stress_target.py`

Loads the vendored CMU dict and returns target stress patterns.

```python
@dataclass
class SyllableTarget:
    syllable: str
    word_index: int
    syl_index_in_word: int
    target_stress: Literal["primary", "secondary", "none"]

def target_pattern(
    prompt_text: str,
    fallback_pattern: str | None = None,  # coach.stress_pattern, used for OOV words
) -> tuple[list[SyllableTarget], Literal["cmudict", "llm-fallback", "mixed"]]: ...

def load_cmudict() -> dict[str, list[str]]: ...
# parses data/cmudict-0.7b.txt once at module import, returns {WORD: [phoneme_list]}
```

**OOV handling:** any word not in CMU dict falls back to the LLM-produced `coach.stress_pattern` for *that word only*. The returned source label is `"cmudict"` if all words came from the dict, `"llm-fallback"` if all came from the LLM, or `"mixed"` otherwise. The template surfaces a subtle indicator only for `"llm-fallback"` and `"mixed"`.

### New: `stress_diff.py`

Pure data, no I/O.

```python
@dataclass
class StressDiffEntry:
    syllable: str
    word_index: int
    syl_index_in_word: int
    target_stress: Literal["primary", "secondary", "none"]
    actual_stressed: bool
    actual_stress_score: float
    status: Literal["hit", "miss", "unexpected", "ok_unstressed", "weak"]

@dataclass
class StressDiff:
    entries: list[StressDiffEntry]
    verdict: str
    target_source: Literal["cmudict", "llm-fallback", "mixed"]

def compute(
    targets: list[SyllableTarget],
    actual: list[PerSyllableProsody],
) -> StressDiff: ...
```

**Status assignment:**
- `hit`: target ∈ {primary, secondary} AND actual_stressed.
- `miss`: target == primary AND NOT actual_stressed. (Misses on primary stress matter; misses on secondary don't generate a verdict.)
- `unexpected`: target == none AND actual_stress_score >= 0.65 (clear extra stress).
- `weak`: target == primary AND 0.4 <= actual_stress_score < 0.55.
- `ok_unstressed`: target == none AND NOT actual_stressed.

**Verdict selection (rule-based, in priority order):**
1. **All-flat fallback:** if no syllable scored >= 0.55, verdict = `"Your delivery is flat — try lifting the stressed syllables to give the sentence shape."`
2. **First miss on a content word:** pick the leftmost `miss` whose word is not a function word (`a, an, the, of, to, for, in, on, at, and, or, but, is, are, was, were, be, been, do, does, did`). Verdict = `f"You stressed {<your_pattern>}. Native rhythm is {<target_pattern>} — {<word_form>} carries the weight on the {<ordinal>} syllable."`
3. **First unexpected on a function word:** verdict = `f"You put weight on '{word}'. In natural rhythm, function words like '{word}' stay light."`
4. **Weak primary stress:** verdict = `f"Your stress on '{word}' was soft — give the {<ordinal>} syllable a stronger lift."`
5. **All hits, no issues:** verdict = `"Stress placement is right on. Try varying pitch range next."`

The pattern strings (`<your_pattern>`, `<target_pattern>`) are word-level renderings like `in-tro-DUCE` vs `IN-tro-duce`, computed for the *single word* the verdict is about (not the whole sentence).

The drill `/drills/attempt` handler additionally calls the new pipeline and passes `stress_diff: StressDiff | None` into the `analysis_card` template context. `None` means the diff couldn't be produced (see Error handling); the template falls back to current layout.

### Modified: `web/templates/partials/analysis_card.html`

New layout, top to bottom:

1. **Verdict box** (rendered only if `stress_diff` is present) — `verdict_box.html` partial: label "One thing to fix" + the verdict sentence. Soft warm-tan background, left border accent, matches existing learning-companion tone.

3. **Two metric chips** — Pitch range, Pauses. Same `score_chip` macro currently in `prosody_metrics.html`, just two of them inline.
4. **"Coach notes & details" drawer** (collapsed by default) — contains: the existing coach transcript/summary/tips, the three demoted chips (Volume, Tempo, Rhythm) using the existing 5-chip macro, target-source indicator if not pure-cmudict.
5. **Audio playback** — unchanged.
6. **Action buttons** — unchanged.

If `stress_diff is None`, the template falls back to the current full 5-chip + coach layout with no verdict box and no syllable strip. No breakage for users on systems where the pipeline degrades.

### Data file: `data/cmudict-0.7b.txt`

Vendored Carnegie Mellon Pronouncing Dictionary. Public domain. Single text file in the canonical CMU format (`WORD  PH PH PH...`). Loaded once at module import into an in-memory dict.

## Data flow at request time

1. User submits recording at `POST /drills/attempt`.
2. Existing pipeline runs: transcription (whisper), `ProsodyAnalysis`, `coach` (LLM).
3. New pipeline runs (in parallel where possible):
   - `target_pattern(prompt_text, fallback=coach.stress_pattern)` → list of `SyllableTarget` + source label.
   - `score_syllables(audio, word_timings, syllable_counts, aligner_result)` → list of `PerSyllableProsody`.
   - `stress_diff.compute(targets, actual)` → `StressDiff` with verdict.
4. Template renders with `stress_diff` in context.

If step 3 raises or returns insufficient data, `stress_diff = None` and the template falls back to current layout. Errors are logged but not surfaced to the user beyond the fallback.

## Error handling & fallbacks

| Situation | Behavior |
|---|---|
| Whisper word timings unavailable (no `word_timings` on the transcript) | `stress_diff = None`. Current 5-chip layout. |
| Recording duration < 1.5s or < 3 syllables detected | `stress_diff = None`. Not enough material for meaningful comparison. |
| All target words are OOV (no CMU hits, no LLM `stress_pattern` either) | `stress_diff = None`. |
| BFA available | Used for tighter syllable boundaries; no fallback needed. |
| BFA unavailable | Whisper-based boundary estimator used; diff still computed. |
| All syllables score below 0.55 (monotone read) | Verdict = "flat delivery" template. Diff entries marked with `ok_unstressed` and `weak` statuses, strip still rendered. |
| `cmudict-0.7b.txt` missing from repo (developer accidentally `gitignore`d it) | At import time, raise a clear `RuntimeError` with the path expected. Test in `test_stress_target.py` guards against this. |

## Testing

New test files:

- **`tests/test_syllable_prosody.py`** — synthetic audio fixtures + canned word timings; assert `stress_score` ordering matches expectation on a 4-utterance fixture set (one clearly-stressed-first, one monotone, one stressed-last, one with a mid-utterance peak).
- **`tests/test_stress_target.py`** — known words from CMU dict assert correct stress positions (`introduce`, `photograph`, noun `record` vs verb `record` — needs explicit per-pronunciation handling), OOV fallback path uses LLM pattern, missing dictionary file raises.
- **`tests/test_stress_diff.py`** — pure data tests: given targets + scored syllables, assert correct entry statuses and verdict selection across the five verdict priority cases.
- **`tests/web/test_routes_drills.py`** (extend existing) — happy path: route returns template context with `stress_diff` populated. Degraded path: short recording → `stress_diff is None`, current layout still renders.

No new test dependencies. Audio fixtures are tiny synthetic WAVs generated by a helper in `conftest.py` (already a pattern in the project).

## Risk register

| Risk | Likelihood | Mitigation |
|---|---|---|
| Whisper-based syllable boundaries are too noisy for reliable stress detection | Medium | Tune sonority weights; BFA upgrade path available; conservative thresholds (`weak` vs `miss` distinction) reduce false-positive verdicts. |
| Stress score weights need tuning per speaker | Medium | Z-scoring within the utterance normalizes against the speaker. Future option: per-user calibration. |
| Verdict templates feel robotic | Low | Keep them terse and specific. LLM-generated coach notes in the drawer provide the conversational layer. |
| Repo size grows by 3.6 MB | Low | Acceptable for an Apache-2.0 project that already stores audio. |
| OOV-heavy prompts produce noisy diffs from LLM fallback | Low | Indicator in UI; user can see when target was AI-derived. |
| Homograph words (e.g. *record* noun vs verb) get the wrong CMU entry | Medium | v1 uses first entry. Acceptable for phase 1 (drill prompts can be written to avoid this, or use the verbforms by default which is the CMU first-entry convention). Future phase: POS-tag the prompt and pick the matching entry. |
